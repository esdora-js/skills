# Design Governance

Use this workflow after docs have been classified.

## Steps

1. Keep universal development obligations in root-level rule outputs.
2. Scope package or domain obligations to their package, app, service, or domain.
3. Convert recurring task procedures into workflows.
4. Convert broad recurring capabilities into skill candidates only when they have distinct trigger language and task routing.
5. Keep background docs as references with source links.
6. Archive or discard stale, duplicated, source-only, secret, or temporary content.
7. Produce a migration plan with validation commands or review checks where available.

## Output

Return:

1. Proposed governance layout.
2. Root rules and domain rules.
3. Workflow candidates.
4. Skill candidates with boundaries.
5. Reference map.
6. Migration checklist.
7. Validation checklist for future AI development.
